# CLAUDE.md

Инструкции для Claude Code (вкладка Code в приложении Claude, VS Code, терминал) по этому проекту.
Общаемся на русском, владелец проекта — Юрий.

## Проект

Игра «Память» (найди пары карточек) на React 18 + Redux Toolkit 2 (react-redux 9) + MUI 5, сборка webpack 5 + Babel.
Готовится к публикации на VK Play / Яндекс Игры. Подробное описание игры и кода — в `README.md`,
история изменений — в `CHANGELOG.md`. Перед работой прочитай README: там структура, правила очков,
уровни, мобильная вёрстка и «Как расширять».

## Команды

```bash
npm install
npm start        # dev-сервер: http://localhost:301
npm run build    # сборка в public/bundle.js (файл лежит в git — без нужды не пересобирать в коммите)
```

Для проверки, что код собирается, не трогая `public/bundle.js`:
`npx webpack --mode production --output-path ./.preview` (папку `.preview` потом удалить).
Автотестов в проекте нет и писать их не нужно (решение владельца).

Как проверять изменения: собрать, открыть игру (`npm start`) и пройти сценарий руками — на компьютере
и в режиме телефона (DevTools, ширина 360–380 px), в светлой и тёмной теме, смотреть ошибки в консоли.
После проверки коротко рассказать владельцу, что проверено, а что нет.

## Правила работы

1. **Документация — вместе с каждым изменением кода**: README, JSDoc-комментарии, CHANGELOG.
   Незакоммиченные изменения записываются в CHANGELOG в раздел `## Не выпущено`; при коммите раздел
   получает дату и короткое название, например `## 22.10.2026 — мобильная версия`.
   Если документация заметно устарела — поправить её в том же изменении.
2. **Коммитить только по команде владельца** («комить»). Сам не коммитить; пушит владелец.
   Сообщение коммита — по-русски: короткий заголовок (что сделано) и пара строк о деталях;
   перед коммитом переименовать раздел «Не выпущено» в CHANGELOG (см. п. 1).
3. **Все хуки (`use…`) — отдельными файлами в `src/hooks/`.** Новые хуки создавать там же.
4. **Переименование файлов — только через `git mv`.** Windows не различает регистр, Linux (и хостинг) различает:
   имя в импорте должно совпадать с именем файла в git буква в букву.
5. Расширение `.jsx` — только у файлов с JSX-разметкой, остальное — `.js`.
6. Не плодить константы ради одного использования: число с понятным комментарием в разметке — нормально.
   Константы — для значений, которые используются в нескольких местах или их часто подстраивают
   (уровни, очки, тайминги).
7. Тексты интерфейса — только через `useTranslation()`, новые ключи — во все 6 языков в `src/dictionary/languages.js`.
8. Вёрстку проверять и на узком экране (телефон, 360–380 px): граница — брейкпоинт `sm` (600 px), хук `useIsMobile()`.
9. Анимации — с отключением при `prefers-reduced-motion: reduce` (так сделаны конфетти, переход экранов, всплывающие очки).
10. Если просьба неоднозначна или невыполнима как есть — спросить, а не угадывать. Например, размер поля
    «колонки × ряды» должен давать чётное число карточек (пары), а число пар у уровня общее для компьютера и телефона
    (на телефоне меняется только число колонок — `mobileColumns`).
11. Если владелец просит откатить изменения — вернуть файлы ровно как было, без «улучшений».

## Где что лежит

- `src/components/` — компоненты (экраны, карточка, кнопки)
- `src/dictionary/` — словари: `languages.js` (тексты интерфейса на 6 языках, язык браузера)
- `src/hooks/` — хуки: `useMemoryGame` (логика партии), `useTranslation`, `useIsMobile`, `useConfetti`
- `src/core/` — чистая логика и данные: уровни, очки, звёзды/прогресс, правила, хранилище, иконки, темы, вибрация, звуки
- `src/store/` — Redux: срезы `gameSlice`, `itemsSlice`, thunk'и `startNewGame` / `finishGame`

## Осторожно

- Звуки (`core/sound.js`) синтезируются Web Audio API, файлов нет. Браузер разрешает звук только после клика
  игрока: первый звук должен раздаваться из обработчика клика (сейчас это щелчок карточки в `openItem`).
- Цвета в теме MUI (`core/themes.js`) — только кодами (`#f5f5f5`), не названиями (`whitesmoke`):
  иначе MUI падает при запуске (ошибка MUI #9) и приложение не отрисовывается.
- Изменения оформления проверять в браузере в обеих темах (светлой и тёмной) и на узком экране.
- Результаты игр хранятся в `localStorage` у игроков: при изменении формата результатов сохранять
  совместимость со старыми записями (см. `src/core/storage.js`, `src/core/progress.js`).
  Изменение числа пар уровня делает его старые рекорды несравнимыми — предупредить владельца.
  Ключи уровней (`veryEasy`, `easy`, `belowMedium`, `medium`, `aboveMedium`, `hard`) лежат в результатах
  и в настройке `level` — не переименовывать; результаты без ключа уровня считаются средним (`LEGACY_LEVEL`).
- `public/bundle.js` лежит в git; пересобирать его (`npm run build`) только когда владелец просит.
- Файлы на диске — с CRLF, в репозитории — LF (`core.autocrlf=true`). Из WSL/Linux git запускать
  с `-c core.autocrlf=true`, иначе все файлы покажутся изменёнными.

## Планы

Цель — публикация на VK Play (возможно, и в Яндекс Играх). Отложено владельцем до отдельной команды:
тематические наборы картинок (нужен источник), PWA, SDK площадки (реклама за подсказку, лидерборд),
управление с клавиатуры, переход на MUI 6/7 (React 18 и последняя MUI 5 — с 23.10.2026).

Идеи, предложенные, но не начатые: превью ссылки
(og-теги); ежедневное задание; достижения;
режим «на время»; продолжение партии после перезагрузки; доступность (подписи карточек для экранных чтецов);
уменьшение бандла.

В Vercel в настройках проекта нужно выставить Node 24.x (сейчас там 14.x).
